The module is organized into three layers:
- Shared layout & chrome: `MainLayoutShell.tsx` wraps page content with `Navbar`, `Footer`, and global overlay drawers (`CartDrawer`, `MegaMenuDrawer`, `SearchModal`, `QuickViewModal`); it detects `/reseller` or `/dashboard` routes to hide public chrome.
- Global app state via React Context in `context/`: `AppContext.tsx` owns cart (localStorage-persisted, DB-synced on auth), wishlist, drawer/modal toggles, and toast; `AuthProvider.tsx` wraps Supabase auth, resolves `seller` vs `customer` roles, and auto-creates a `users` profile row when missing.
- Page components at the top level (`ProductDetailPage`, `CollectionPage`, `CartPage`, `CheckoutPage`, `OrderSuccessPage`, `TrackOrderPage`, `AccountPage`, `EmailVerificationPage`, plus static/legal pages) consume both contexts and use TanStack Query + Supabase for data fetching. `ResellerStorefront.tsx` is a self-contained seller storefront with its own query keys, infinite-scroll pagination, category chips, and skeleton components.
- A sibling `reseller/` sub-tree is an isolated admin portal: `ResellerDashboard.tsx` boots `ResellerProvider` from `reseller/context/ResellerContext.tsx`, which owns listing/order/wallet state; `reseller/components/` holds per-feature views (Orders, Listings, Analytics, Payouts, Reviews, Settings) and shared primitives under `reseller/components/common/`. The reseller portal is visually and state-wise separate from the public storefront shell.
Dependency direction is one-way: page components → `useApp` / `useAuth` → Supabase API layer (`@/src/api/*`); the reseller subtree does not import from the public page components.
